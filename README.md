# Первое приложение на Django

## Суть проекта:

Разрабатываем первое приложение на django. 

### Технический стек:
В проекте используются:

* Менеджер пакетов `Poetry`.
* Фреймворк `Django`

Для проекта требуется версия python не ниже `3.13`, Poetry не ниже `2.0.0` и Django не ниже версии `6.1.1`

### Установка:

1. Склонируйте проект на свое локальное окружение командой:  
   git clone https://github.com/Uriy-T/skypro_UI_base.git

2. Убедитесь, что в среде разработки для проекта используются интерпретатор python  
   и poetry версии в соответствии с указанными требованиями.

3. Для установки всех необходимых зависимостей выполните команду:
   ```bash
   poetry install

### Реализация

На момент сдачи в реализации: 
* создан базовый Django проект;
* создано приложение `catalog`;
* реализованы контроллеры обращения к страницам `home/` и `contacts/`;
* настроены пути к реализованным контроллерам на уровне приложения и проекта.

В проекте используются готовые шаблоны предоставленные в задании, а так же отовые стили и javascript скрипты из bootstrap.

Реализована логика контроллера `contacts/` позволяющая отправлять сообщения из формы обратной связи страницы. С последующим отображением системного сообщения об успешности действия.

## Версия в контексте лабораторной по лекции 26.1
В ходе работы реализованы следующие пункты:
1. Реализован модуль `product_forms.py` в пакете `forms` приложения `catalog`
2. В модуле product_forms.py реализован класс `ProductForm` используемый для отображения форм создания и редактирования товаров каталога.
В классе реализованы:
* Методы валидации данных в полях `Название продукта`, `Описание продукта`, `Цена продукта` и прикрепляемого к продукту `изображения-иллюстрации`. Валидаторы основаны на работе с методом Django `cleaned_data`.
* компановка полей формы и их стилизация на основе переопределения метода `__init__` и метода `widget.attrs.update`.
3. Контроллеры соответствующих форм переведены на работу с реализованной формой.
4. Подшаблоны соответствующих форм адаптированы на работу с реализованной формой.
5. Основной шаблон и подшаблон футтера адаптированы под работу, в том числе с формами на основе Django классов. Футтер динамически сдвигается по высоте, если основной контент страницы превышает высоту области видимости. В противном случае, прикреплен к нижней части области вилдимости.
6. Файл настроек `configuration.py` расширен настройками ограничений для валидации форм создания и редактирования товара:
* Можно настраивать список запрещенных слов в полях названия и описания продукта - RESTRICTED_WORDS.
* Можно настраивать список форматов изображений разрешенных для прикрепления к карточке товара - P_IMAGE_TYPES.
* Можно менять максимальное ограничение размера файла изображения - P_SIZE_LIMIT.
